# 集客・市場向けポータル（Acquisition Portal）事業・技術定義書

**プロジェクト名：** Share House OS (仮称: EnShare)
**作成日：** 2026年3月15日 ｜ **バージョン：** 3.0 ｜ **機密区分：** Confidential

## 1. プロダクトの目的と提供価値

### 1.1 位置づけ

Acquisition Portalは、Share House OSエコシステムにおける「市場との接点（フロントドア）」です。
既存の不動産ポータルとは一線を画し、Core OSに蓄積された既存住民の匿名化データ（House Stats）を公開することで、「カルチャーフィット（相性）」をベースにしたミスマッチのない集客を実現します。さらに、ネットワーク内の流動性を高める「ワンクリック引越し」のエントランスとしても機能します。

### 1.2 解決するペイン

| ステークホルダー | 抱えている強烈なペイン | Acquisition Portalによる解決策（ソリューション） |
| --- | --- | --- |
| **入居検討者** | **内見に行かないと雰囲気が分からない**<br>

<br>写真だけでは「どんな人が住んでいるか」「自分とノリが合うか」が分からず、内見のハードルが高い。 | **Community Vibe Report:**<br>

<br>現在の住民の「MBTI分布」「年代」「生活リズム」をデータで可視化し、内見前にカルチャーフィットを判定させる。 |

## 2. マネタイズ手法・財務インパクト

### 2.1 B2B2C マーケットプレイス収益（トランザクション）

Acquisition Portalは、SaaS（Owner Console）の導入物件が増えるほど掲載物件が自動的に増えていく「SaaS Enabled Marketplace」として機能します。

* **① ワンクリック引越しのシステム移行手数料（住民課金）**
* **単価:** 9,800円 / 回
* **提供価値:** 通常数十万円かかる初期費用をスキップできる権利。流動性が高まる（住民がハウス間を移動する）たびに、プラットフォームに手数料が落ちるチャリンチャリンモデル。


* **② 外部オーナーからの成果報酬型 送客手数料（B2B課金）**
* **単価:** 1件成約あたり 30,000円 〜 50,000円（※ひつじ不動産等の相場より安く設定）
* **提供価値:** 「カルチャーフィットを事前に確認し、納得した上で応募してくる優良顧客」の送客。



### 2.2 プラットフォームとしての「鶏と卵の問題」の突破

通常のポータルは「物件がないと客が来ない、客がいないと物件が載らない」という死の谷に陥りますが、本ポータルは**「すでにOwner Console（SaaS）を使っている物件の空室が、自動的にポータルに同期される」**構造になっています。営業コストをかけずに掲載物件（サプライ側）を担保できる点が、財務面での最大の競争優位性です。

## 3. 主要機能一覧

### 3.1 Community Vibe Report（House Stats）

* **属性データの匿名化ウィジェット:**
Core OSの `profiles` テーブルから、該当物件の住民データを集計。「INFPが多めの静かな環境」「20代後半のエンジニア・クリエイター中心」「自炊派が8割」といったコミュニティの空気感を、円グラフやインフォグラフィックで洗練されたUIで表示。
* **オーナー向けLP埋め込み機能:**
このウィジェットを、オーナーが自社のホームページや他の募集サイト（SUUMO等）に `<iframe>` やスクリプトタグで埋め込めるようにする（強力な外部からの被リンク・トラフィック獲得動線）。

### 3.2 セルフ内見（Guest Pass 発行）

* **時限式アクセス権限:**
ポータル上で「詳しく見る」をリクエストしたユーザーに対し、24時間限定の Guest Pass（Magic Link）を発行。
* **Resident Appの体験:**
個人情報やリアルタイムのトラブルチケットはマスク（RLSで制御）した状態で、実際のハウスルール、ゴミ出しカレンダー、過去のTea Timeの開催実績などを閲覧させる。

### 3.3 ワンクリック引越し（ファストパス・エントリー）

* **信用スコアによる条件分岐:**
ポータルにログイン（Supabase Auth）した状態で物件を閲覧した際、ユーザーの `credit_score` が基準値（例: 700点以上）を満たしていれば、画面上に「👑 Fast Pass: 初期費用ゼロ・無審査で即時契約可能」というVIPボタンが出現。
* **シームレスな契約移行:**
ボタンを押すと、Owner Console側の電子契約パイプラインに直接データが送られ、Stripe Checkoutでのシステム手数料決済と同時に新物件の契約が完了する。

## 4. 技術要件・アーキテクチャ案

### 4.1 推奨技術スタック

* **フレームワーク:** Next.js 16 (App Router)
* SEO対策が必須の集客ポータルにおいて、サーバーサイドレンダリング（SSR）と静的サイト生成（SSG）を柔軟に組み合わせられる最強の選択肢。物件一覧ページはSSG（ISRで定期更新）、Vibe Reportなどの動的データはSuspenseを使ったSSRで実装。


* **スタイリング & アニメーション:** Tailwind CSS + Framer Motion
* 「環境であり主役ではない」という原則に従い、Framer Motionを用いた"静かで控えめなアニメーション（フェードインやスムーズなページ遷移）"を実装し、高級感と信頼感を演出。アクセントカラーにCyan/Teal（immedio style）を採用。


* **バックエンド通信:** Supabase JavaScript Client
* `properties`（公開設定がONの物件のみ）と、匿名化された統計データをフェッチ。



### 4.2 主要コンポーネントとデータ連携ロジック

#### A. 動的物件詳細ページ (`/properties/[id]`)

* **ロジック:**
`generateStaticParams` で公開中の物件ページの静的HTMLを事前生成し、爆速の表示速度（Core Web Vitalsの最適化）を実現。
* **データフェッチ:**
Core OS側で用意した「匿名統計データ集計用のDBビュー（またはRPC）」を叩き、リアルタイムの住民属性（Vibe Report）を安全に表示する。

#### B. Guest Pass 発行モジュール (`/components/GuestPassRequest`)

* **ロジック:**
ユーザーがメールアドレスを入力すると、Supabase AuthのMagic Linkを送信。同時に、対象ユーザーの `role` を一時的に `guest` に設定し、該当物件の `property_id` への閲覧権限を24時間だけ付与する（DBのトリガー関数で期限切れ後に権限を剥奪）。

### 4.3 SEO・パフォーマンス・セキュリティ考慮事項

* **SEO最適化（Next.js Metadata API）:**
各物件ページに対して、動的な `title`, `description`, およびOGP画像（物件のカバー画像）を自動生成。検索エンジンからのオーガニック流入を最大化。
* **情報のマスキング（セキュリティ）:**
集客ポータルからCore OSへクエリを投げる際、絶対に個人の特定（名前や生年月日、正確な部屋番号など）ができないよう、SupabaseのRow Level Security (RLS) とデータベースビューのレベルで厳格にデータをマスキングする。

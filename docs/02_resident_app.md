# 住民向けアプリ（Resident App）事業・技術定義書

**プロジェクト名：** Share House OS (仮称: EnShare)
**作成日：** 2026年3月14日 ｜ **バージョン：** 3.0 ｜ **機密区分：** Confidential

## 1. プロダクトの目的と提供価値

### 1.1 位置づけ

Resident Appは、シェアハウスに暮らす住民が毎日触れる「生活インフラ」であり、同時に「自身の信用スコア（Resident Credit）を育成するゲーミフィケーション・インターフェース」です。
「引き算のデザイン（無印良品的UI）」を徹底し、いいね数やフォロワーといったSNS的ノイズを排除。住民に過度な交流を強制することなく、「静かな自治」と「心地よい距離感」をソフトウェアの力で維持します。裏側では常に **Core OS** と同期し、住民のあらゆるポジティブ・ネガティブな行動をデータとして蓄積します。

### 1.2 解決するペイン

| ステークホルダー | 抱えている強烈なペイン | Resident Appによる解決策（ソリューション） |
| --- | --- | --- |
| **住民** | 直接注意できないストレス（騒音、共有部の私物化など、LINEで名指しで怒れない気まずさ） | **Silent Report（匿名通報）:** システム経由で匿名報告し、一定数で全体アラートを自動発火。人間関係の摩擦をゼロにする。 |
| **住民** | 掃除当番などの「やりたくない義務」による不公平感やモチベーション低下 | **House Quests（クエストボード）:** 義務を廃止し、ギグエコノミー化。掃除をした人が「家賃割引ポイント」を得る報酬系へ転換。 |
| **住民** | 他の住民の顔や名前、温度感が分からず、共有部で話しかけるハードルが高い | **プロフィール＆Tea Time:** MBTIや生活リズムを事前把握でき、週1回のランダムマッチで「自然な交流の言い訳」を提供する。 |
| **オーナー** | 住民間のトラブルや、ルール違反に対する「終わりのないクレーム対応」 | **Rule Governance（DAO型投票）:** ルール設定の責任を住民側に委譲し、オーナーを「ルールの決定者（悪者）」から解放する。 |

## 2. マネタイズ手法・財務インパクト

### 2.1 財務的立ち位置（コスト削減のエンジン）

Resident App自体は住民に無料で提供されるため、直接的な売上（サブスクリプション収益）は生み出しません。しかし、このアプリが稼働することで、オーナー向けの「Owner Console（B2B SaaS）」の価値を極大化し、**オーナーの莫大な管理コストを直接的に削減（Cost Saving）**します。

### 2.2 ハウスエコノミー（House Economy）によるコスト削減ロジック

これまでオーナーが外部業者に支払っていたキャッシュアウトを、住民への「ポイント（家賃割引）」に変換する内部経済圏を構築します。

* **従来のオーナーの支出（月額）：**
清掃業者委託費（30,000円）＋ 備品補充・管理工数（10,000円）＝ **計 40,000円の流出**
* **Resident App導入後（月額）：**
住民へのポイント付与（クエスト報酬等で最大 15,000円分の家賃割引）＝ **計 15,000円の流出**
* **財務インパクト：** 1物件あたり **月額 25,000円の利益率改善**。これがオーナーにとって、当プラットフォームのSaaS利用料（月額20,000円等）を支払ってもお釣りが来るという強力な導入根拠（ROI）となります。

## 3. 主要機能一覧

### 3.1 住民の自治を促す「House Economy（ハウス経済圏）」

* **House Quests（クエストボード）：**
「キッチンの換気扇掃除（500pt）」「トイレットペーパーの補充（実費＋100pt）」など、Core OSから自動生成されるタスク一覧。完了写真をアップロードし、承認されるとポイント（翌月家賃割引）を獲得。
* **Thanks Tokens（ありがとうコイン）：**
住民間で月間一定枠のポイントを送り合うピアボーナス。コミュニティのキーマンを可視化し、受領数に応じてResident Credit（信用スコア）が加点される。
* **Buddy System（バディ制度）：**
新規入居者が来る際、既存住民がアプリから「案内役」に立候補。ハウスツアーやルールの説明を完了すると高額ポイント（例: 2000pt）を獲得。オーナーの現地案内工数をゼロにする。

### 3.2 資産と平穏を守る「防衛・自治機能」

* **Room Condition Tracker（原状回復の証拠保全）：**
入居後3日以内に、住民自身のスマホカメラで自室の「元からある傷や汚れ」を撮影し、アップロードする必須タスク。未完了の場合はアプリの他機能がロックされる。退去時の敷金水掛け論を完全に防ぐ。
* **Silent Report（匿名トラブル通報）：**
「深夜の騒音」などを匿名で通報。Core OS側で集計され、3件溜まると「全体への注意喚起プッシュ通知」が自動送信される。
* **Rule Governance（DAO型ルール投票）：**
住民が「24時以降の共有TV使用禁止」などの新ルールを起案。住民全員による匿名投票で可決ライン（例: 70%）を超えれば、アプリ内の「House Rules」に自動追記される。

### 3.3 日常インフラ・交流・スコア管理

* **My Credit Dashboard（信用スコア・ポイント確認）：**
現在の自分の保有ポイント（家賃割引額）と、「Resident Credit（信用スコア：0〜1000）」を可視化。スコアを上げるためのネクストアクション（例: 「クエストをこなしましょう」）をレコメンド。
* **Tea Time & Share Board：**
週1回のランダムマッチング機能（オプトイン式）と、余った食材・日用品を「あげる・もらう」掲示板。
* **Smart Info（生活インフラページ）：**
Wi-FiのSSID/PASS（タップでコピー）、ゴミ出しカレンダー、契約更新の通知受け取り機能。

## 4. 技術要件・アーキテクチャ案

### 4.1 推奨技術スタック

* **フレームワーク:** Expo (React Native) - Web版のNext.jsとTypeScriptの型定義をTurborepoで共有し、iOS/Androidへ同時コンパイル。
* **UIコンポーネント:** NativeWind (Tailwind CSS for React Native) - 「引き算のデザイン」を効率よく実装。
* **バックエンド通信:** `@supabase/supabase-js` - Core OS（Supabase）との直接通信。
* **認証:** Supabase Auth (Magic Link または Email/Password) - 住民の初回ログイン用。
* **画像処理:** `expo-image-picker` および `expo-image-manipulator` - Room Condition TrackerでのHEIC対応・自動圧縮・EXIF保持（位置情報と撮影日時の改ざん防止）。

### 4.2 主要コンポーネントとデータ連携ロジック

#### A. 信用スコア＆ウォレット画面 (`/screens/WalletScreen`)

* **ロジック:** Core OSの `point_balances` と `trust_scores` テーブルをリアルタイム購読（Supabase Realtime）。
* **UX:** 毎月の「家賃割引予定額」が大きく表示され、Stripe Invoiceへの適用状況が視覚的にわかる。

#### B. クエスト＆写真アップロード (`/screens/QuestScreen`)

* **ロジック:** 1. 住民がタスクを受注し、写真を撮影。
2. 画像を Supabase Storage の `quest-proofs` バケットにアップロード（RLSで本人のみ書き込み可能）。
3. 完了ステータスを `economy_ledgers` テーブルに `INSERT`（ステータスは `pending_approval`）。

#### C. サイレント通報 (`/screens/ReportScreen`)

* **ロジック:**
1. 報告内容を `trouble_tickets` テーブルに `INSERT` (`is_anonymous: true`)。
2. Core OS上の Edge Function (Deno) がトリガーされ、対象物件の過去7日間の同種レポート数をカウント。
3. 閾値（例: 3件）を超えた場合、Expo Push Notifications API 経由で対象物件の全住民に自動アラートを送信。



### 4.3 オフライン・エッジケース対応

* **キャッシュ戦略:** Wi-Fiのパスワードやハウスルールなど、生活に必須の静的情報は `AsyncStorage`（または `expo-secure-store`）にキャッシュし、オフライン環境（電波の悪い共有部など）でも閲覧可能にする。
* **プッシュ通知の「静けさ」:** 朝のダイジェスト（1日1回）以外のプッシュ通知は原則オフとする。ただし、ルール投票の開始や、全体アラート（サイレント通報結果）のみ、例外的に即時通知（Critical Alert）として扱う。
